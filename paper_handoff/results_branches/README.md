# Two Result Branches: How to Use and How to Choose

## Files
| File | Purpose |
|---|---|
| `results_macros_DRAFT_expected.tex` | **Expected (good-case) values, for drafting only.** Every number renders red with a †; unknown values render as a red `[?]`. It aborts compilation if `\SubmissionBuild` is defined |
| `results_macros.tex` | **Generated by `analysis/export_tex.py` from `results/*/summary.csv`.** This is the only macro file allowed in the submission |
| `branch_A_claims.tex` / `branch_A_results.tex` | Branch A (expected outcome): result sentences for the abstract, intro and discussion, plus the full Results section |
| `branch_B_claims.tex` / `branch_B_results.tex` | Branch B (ordinary outcome): same macros, more conservative prose; `%IF` comments mark sentences that depend on a condition |

## Wiring into main.tex
Preamble (after `\usepackage{...}`):
```latex
% \def\SubmissionBuild{}             % uncomment for the submission build
\newcommand{\ResultsBranch}{A}         % A or B; chosen by the rule below
\input{results_macros_DRAFT_expected}  % drafting; replace by \input{results_macros}
\input{branch_\ResultsBranch_claims}
```
Then:
- in the abstract, replace the last three sentences with `\AbstractResults`;
- in the Introduction, replace "The outcome evidence is \ResultConclusion." with `\IntroEvidence`;
- replace the whole current `\section{Results}` … (up to Discussion) with
  `\input{branch_\ResultsBranch_results}`, and keep the figure/table environments (moving them
  into the branch file is also fine);
- in the Discussion, replace "The completed evaluation supports \ResultConclusion." with `\DiscussionResults`;
- delete the old `\SilentEffect`, `\BudgetEffect`, … definitions.

The main table (`tab:main`) and the figure data are written as `tab_main.tex` / CSV by the
export script; they are never typed by hand.

## Choosing the branch (decide from the frozen results only)
| Condition (primary endpoints, Holm-adjusted) | Branch |
|---|---|
| P-1 (ΔW_silent, C7r − C6, S1 κ=2) significant **and** P-2 (ΔW, C7r − C2*) significant and positive | **A** |
| P-1 significant, P-2 not significant (or CI includes 0) | **B**; then keep or delete the `%IF` sentences according to the TOST result and the IPW main-effect CI |
| P-1 not significant | **Neither.** Stop and reconsider the framing with the full results; do not force either text |
| P-2 significantly **negative** | B with a mandatory added sentence reporting the population-welfare cost; discuss it as a trade-off |

Mixed cases inside a branch (for example, the E2 advantage at scarce budgets is not
significant; the S0 gain is null; C9 ≥ C7r) are handled by editing the affected sentence to
report the observed direction. Never keep a sentence whose direction the data contradict.

## Mandatory checks in `export_tex.py` (fail loudly)
1. Every macro used in the branch files is defined in `results_macros.tex` (no `\pendnum`, no `\draftnum`).
2. Provenance: every summary row comes from runs whose manifest has `backend=vllm`, the `prereg-v1`
   tag, and eval seeds only.
3. E4b: the deviation from the clean-parser target at ε_p = 0 equals 0 (±1e-12). `vDev*` and `vErr*`
   are different metrics and are exported separately.
4. Equal resources: accepted visits across E1 conditions lie within ±5% of C7r (otherwise the "reflect
   allocation rather than volume" sentence is removed, and the script prints a warning).
5. C10 has the highest W, W_min and W_silent (otherwise print a warning: possible bug).
6. The n values printed in captions equal the realized seed counts.
7. `vGapW = 100·(W_C7r − W_C1)/(W_C10 − W_C1)`, and likewise for `vGapWm`; computed, never typed.
8. p-values are formatted consistently (`<0.001` below 1e-3; 2–3 significant digits otherwise); CIs
   come from 10,000 paired bootstrap resamples.

## Note on the expected values
The expected E4b table does not contain the deviation-from-clean metric; it must be 0 at ε_p = 0.
The expected "policy error" numbers correspond to `vErr*` (distance to the C10 reference), and
the `vDev*` macros stay `[?]` in the draft. S0/S2a/S2b, C6q, TOST and the cap-activation rate have
no expected values and also render `[?]`.
